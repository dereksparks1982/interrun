# Interrun Project Rules

## Repository shape

Interrun is a **beanpole, not a tree**.

- Exactly one development branch: `main`.
- No feature branches.
- No bootstrap branches.
- No pull-request branches for normal project work.
- Approved work moves `main` forward in a straight line.

## Change control

- Scope first.
- Do not change working areas outside the approved scope.
- Warnings are treated as errors.
- Do not guess about donor code; inspect it first.
- Rejected builds do not become the baseline.

## User-control rules

- No required cloud account.
- No proprietary service required for core operation.
- Local profiles are authoritative.
- P2P is preferred for direct person-to-person communication.
- Communications are designed for end-to-end encryption.
- Third-party cookies are blocked by default.
- Site storage must be visible and controllable.
- No advertising telemetry or sale of user data.

## Donor-code rule

Existing work from DK Media and Nougat should be reused when it already solves a problem. Imported code must keep a clear source/licensing trail.
